# AGENTS.md

This repository contains the client-side JavaScript and CSS source used by the FooGallery WordPress plugin and related FooGallery addons. It is usually consumed as the `client` submodule from the parent `foogallery` plugin repository.

## Architecture

- `src/core/js/` contains shared FooGallery runtime code.
- `src/core/css/` contains shared FooGallery styling.
- `src/core/js/items/` defines gallery item parsing, creation, serialization, and item-specific behavior.
- `src/core/js/panel/` defines the FooGallery panel/lightbox system, including panel areas, buttons, and media renderers.
- `src/core/js/filtering/` and `src/core/js/paging/` contain optional feature components.
- `src/templates/` contains template-specific JS/CSS for gallery layouts such as default, masonry, justified, portfolio, image viewer, carousel, slider, and FooGrid.
- `src/albums/` contains album-specific client code.
- `src/admin/` contains wp-admin client code.
- `polyfills/` contains browser polyfills that are bundled as standalone component assets.
- `docs/` contains client documentation and generated documentation support files.
- `dist/` is generated by Grunt and is ignored by git. Do not treat it as source.
- `test-pages/` contains local static test pages and generated test-page assets.

## Build System

The build is driven by `Gruntfile.js`.

Install dependencies before building:

```sh
npm install
```

Run the full build:

```sh
npm run build
```

The full build:

1. Cleans `dist/`.
2. Builds reusable component assets under `dist/components`.
3. Concatenates Free and Pro FooGallery bundles under `dist/free` and `dist/pro`.
4. Minifies JS and CSS.
5. Copies generated assets into local `test-pages/*/assets` directories.

Generated files under `dist/` and `test-pages/*/assets` are not committed in this repo.

## Core Bundles

The main Grunt targets are:

- `concat:core` and `concat:core_pro` for shared core runtime assets.
- `concat:panel` and `concat:panel_pro` for the panel/lightbox runtime.
- `concat:paging`, `concat:paging_pro`, and `concat:filtering` for optional features.
- `concat:<template>` targets for template-specific components.
- `concat:free` and `concat:pro` for the final Free and Pro bundles.

When changing source that belongs in FooGallery core, update the relevant source file and run the full build. Do not patch generated bundles directly.

## Addons

FooGallery addon client assets should be developed from this repo so all addons follow the same source/build/deploy pattern.

Use the Social addon as the baseline:

- source lives under `src/core/js/social/` and `src/core/css/social/`
- `Gruntfile.js` has a `concat:social` component target
- the build emits `dist/components/js/foogallery.social(.min).js` and `dist/components/css/foogallery.social(.min).css`
- `npx grunt social` copies those built files into `../../foogallery-social/assets/js` and `../../foogallery-social/assets/css`
- the addon plugin enqueues the copied assets through FooGallery feature dependency hooks

For detailed addon asset workflow, read [docs/addon-assets.md](docs/addon-assets.md).

The 3D Walkthrough addon follows the same pattern:

- source: `src/core/js/3d-walkthrough/` and `src/core/css/3d-walkthrough/`
- build task: `npx grunt 3d-walkthrough`
- copied outputs: `../../foogallery-3d/assets/js` and `../../foogallery-3d/assets/css`

Proofing also has client source in this repo:

- source: `src/core/js/proofing/` and `src/core/css/proofing/`
- component target: `concat:proofing`
- build task: `npx grunt proofing`
- component outputs: `dist/components/js/foogallery.proofing.panel(.min).js` and `dist/components/css/foogallery.proofing.panel(.min).css`
- copied outputs: `../../foogallery-proofing/assets/js` and `../../foogallery-proofing/assets/css`
- note: the Proofing addon currently ships public, admin, and panel asset groups; only the panel asset group is generated from this client repo

## Development Rules

- Source edits belong under `src/`, not `dist/`.
- Addon source belongs in this client repo; addon plugin `assets/` files are distribution outputs.
- If an addon ships copied assets, commit source changes in this repo and built assets in the addon repo.
- If this repo is used as a submodule from the parent FooGallery repo, commit the updated submodule pointer in the parent repo after committing client changes.
- Prefer adding a focused Grunt task for addon-only builds when an addon has a local plugin repo.
- Keep new component targets in `Gruntfile.js` close to related targets, and write outputs under `dist/components`.
- Use existing FooGallery runtime extension points instead of editing core generated bundles for addon behavior.

## Verification

Before handing off client or addon asset changes:

1. Run the relevant syntax check, for example `node --check <file>.js`.
2. Run the focused addon build task or `npm run build`, depending on the scope.
3. Confirm generated addon assets match the files copied into the addon repo.
4. Smoke-test a gallery with the addon active when behavior changes.
5. Confirm working trees are clean, except for intended parent submodule pointer updates.
